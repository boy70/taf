PROJECT OVERVIEW
================================================================================
Tafsula is a Next.js 14 SaaS platform that analyzes startup team compatibility 
using the DISC personality model. It helps startups understand their team 
dynamics and improve collaboration through AI-powered insights.

Project Name: my-v0-project (Version 0.1.0)
Tech Stack:
- Frontend: Next.js 14 (App Router), React 19, TypeScript
- Backend: Next.js API Routes, Server Actions
- Database: MySQL with Prisma ORM
- Authentication: NextAuth.js with JWT strategy
- AI Integration: Hugging Face API (Mistral-7B model)
- UI Components: Radix UI, Shadcn UI, Tailwind CSS
- Animations: Framer Motion
- Icons: Lucide React

================================================================================
DATABASE SCHEMA (PRISMA)
================================================================================

Core User & Authentication Models:
- user: Stores user info (id, name, email, hashed password, role, startup)
- startup: Represents a company/organization (id, name, createdById)
- profile: User profile with bio, headline, experience, skills, personality

DISC Personality Test Models:
- question: Test questions with DISC mappings (id, questionText, discMapping)
- answer: User's selected answers to questions (userId, questionId, agreementLevel)
- result: Calculated DISC scores per user (dScore, iScore, sScore, cScore, dominantType)
- insight: AI-generated personality feedback text per user

Team & Organization Models:
- team: Teams within startups (id, startupId, name, purpose, members, projects)
- teamMember: Links users to teams (teamId, userId, roleInTeam)
- project: Projects within startups (id, startupId, title, type, status, teamId)
- task: Tasks within projects (id, projectId, title, assigneeId, dueDate)

Skills & Development Models:
- skill: Skill database (id, name, category)
- userSkill: User skill assignments with levels (userId, skillId, level)
- certificate: User certificates and credentials (userId, title, issuer)
- training: Training recommendations (generated via API)

Proposal & Governance Models:
- proposal: Proposals/initiatives (id, startupId, title, type, status, canvasJson, swotJson)
- proposalComment: Comments on proposals (proposalId, authorId, body)

Event & Resource Models:
- event: Events and training sessions (id, startupId, title, type, startAt, endAt)
- attendance: Event attendance tracking (eventId, userId, status)
- resource: Learning/organizational resources (id, startupId, title, type, url)

User Roles (Enum):
- SUPERADMIN: Full access to all data and features
- HR: Access to startup data, employees, team management
- EMPLOYEE: Can take tests, view personal results
- REGULAR_USER: Limited access

API ENDPOINTS (BACKEND ROUTES)
================================================================================

Authentication Endpoints:
- POST /api/auth/[...nextauth]: NextAuth.js authentication handlers
  * Credentials provider (email/password)
  * JWT session strategy
  * User role and startup info in session token

Test Management Endpoints:
- GET /api/test/questions: Fetch 20 randomized DISC test questions
  * Returns: Array of questions with options and DISC mappings
  * Auth: Required (session)
  
- POST /api/test/submit: Submit test answers and calculate DISC scores
  * Input: { answers: Array<{questionId, agreementLevel}> }
  * Calculates: D, I, S, C scores and dominant type
  * Generates: AI insight using Hugging Face API
  * Auth: Optional (handles both logged-in and anonymous users)
  
- GET /api/test/results: Fetch user's latest test results
  * Returns: { result: DISC scores, insight: AI feedback }
  * Auth: Required (JWT token)

User Management Endpoints:
- GET /api/users: List users (with filters for startupId, role)
  * Query params: startupId, role, userId
  * Auth: Required
  
- POST /api/users/invite: Invite new users to startup
  * Input: { email, role, startupId }
  * Creates: New user with invitation link
  * Auth: Required (HR or SUPERADMIN)
  
- PUT /api/users/[id]/role: Update user role
  * Input: { role: USER_ROLE }
  * Auth: Required (SUPERADMIN or HR)

Startup Management Endpoints:
- GET /api/startups: List all startups
  * Auth: Required
  
- POST /api/startups: Create new startup
  * Input: { name }
  * Auth: Required (SUPERADMIN only)
  
- GET /api/startups/[id]: Get specific startup details
  * Returns: Startup data with employee count, team info
  * Auth: Required

Team Management Endpoints:
- GET /api/teams: List teams (filtered by startup)
  * Auth: Required
  * Includes: members, projects info
  
- POST /api/teams: Create new team
  * Input: { name, purpose, description, status, visibility, leadIdsJson }
  * Auth: Required (HR or SUPERADMIN)
  
- GET /api/teams/[id]: Get specific team details
  * Returns: Team info with members and projects
  
- PATCH /api/teams/[id]: Update team details
  * Input: Team update data
  
- POST /api/teams/[id]/members: Add member to team
  * Input: { userId }
  
- DELETE /api/teams/[id]/members/[userId]: Remove team member

Project Management Endpoints:
- GET /api/projects: List projects (with visibility filters)
  * Returns: Projects with teams and task counts
  * Auth: Required
  
- POST /api/projects: Create new project
  * Input: { title, description, type, status, teamId, timeline, objectives }
  * Auth: Required (HR or SUPERADMIN)

Task Management Endpoints:
- PATCH /api/tasks/[taskId]: Update task status/assignment
  * Input: Task update data
  * Auth: Required

Proposal Management Endpoints:
- GET /api/proposals: List proposals (with visibility/role filters)
  * Returns: Proposals with submitter and reviewer info
  
- POST /api/proposals: Create new proposal
  * Input: { type, title, canvasJson, swotJson, timeline, expectedImpact }
  * Auth: Required

Event Management Endpoints:
- GET /api/events: List events (with role-based visibility)
  * Returns: Events ordered by start time
  
- POST /api/events: Create new event
  * Input: { title, type, visibility, description, startAt, endAt, location, skills, relatedTeamId, relatedProjectId }
  * Auth: Required (HR or SUPERADMIN)

Skills Endpoints:
- GET /api/skills: List all available skills
  * No auth required
  
- POST /api/skills: Add new skill to database
  * Input: { name, category }
  * Auth: Required (HR or SUPERADMIN)
  
- POST /api/skills/assign: Assign skill to user
  * Input: { userId, skillId, level }
  * Auth: Required

User Profile Endpoints:
- GET /api/profiles/[userId]: Get user profile with DISC results
  * Returns: Full user profile, certificates, skills, personality snapshot
  * Auth: Required (with authorization checks)
  
- PATCH /api/profiles/[userId]: Update user profile
  * Input: Profile update data (headline, bio, experience, skills)

Results Endpoints:
- GET /api/results/[userId]: Get user's DISC test results
  * Returns: Latest result with scores and dominant type
  * Auth: Required (with authorization checks)

Training Endpoints:
- GET /api/training/[userId]: Get training recommendations
  * Calls: Hugging Face API for personalized training plan
  * Returns: Training plan based on DISC type and dominant personality
  * Also returns: Communication tips based on personality

Resource Management Endpoints:
- GET /api/resources: List resources (with filters)
  * Query params: startupId, type, visibility
  
- PATCH /api/resources/[id]: Update resource details
  * Input: Resource update data

Compatibility Analysis Endpoints:
- (Implemented via library functions, not direct API route)
- Function: calculateTeamCompatibility(teamMembers)
- Returns: Balance score, strengths, weaknesses, recommendations

DISC Compatibility Analysis (lib/compatibility.ts):
- calculateTeamCompatibility(teamMembers): Calculate team balance and recommendations
  * Counts DISC types distribution
  * Calculates average scores per type
  * Generates balance score (0-100)
  * Returns strengths, weaknesses, and recommendations

AI Integration (lib/huggingface.ts):
- generateInsight(discResult): Generate AI insight for DISC personality
  * Uses Mistral-7B model via Hugging Face API
  * Input: DISC scores and dominant type
  * Output: Detailed workplace profile including work style, communication style, strengths, growth areas, ideal environment
  
- generateTrainingPlan(dominantType, userName): Generate personalized training plan
  * Creates development recommendations based on personality type
  * Includes specific action items and resources
  
- generateCommunicationTips(dominantType): Generate communication style tips
  * Provides advice for optimal communication with different types

Email (lib/email.ts):
